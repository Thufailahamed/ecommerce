# Database design

The source of truth is `packages/database/src/schema.ts`. Migrations are in `packages/database/migrations`; each is
generated by drizzle-kit, extended with hand-written backfills where needed, and has its own test in
`packages/database/src/migration-*.test.ts`. They are applied explicitly with `wrangler d1 migrations apply`, never
pushed.

## Conventions
- Text ids with a type prefix (`sto_`, `cmp_`, `evt_`…). ISO-8601 UTC text timestamps.
- Every tenant table carries `store_id` (or `organization_id`), and every read filters on it.
- Secrets live apart from business rows (`integration_credentials`, `provider_connections.encrypted_credentials`) and
  are AES-GCM encrypted.
- Raw storefront events are never stored. Only a short-retention dedup ledger and daily aggregates are kept.
- History is append-only where it is evidence: `campaign_versions`, `consent_events`, `audit_logs`, `domain_events`.

## Relationships (tenancy spine)

```
organizations ─┬─ memberships ── users
               ├─ subscriptions, usage_records, organization_features   (0009)
               ├─ domain_events ── domain_event_deliveries          (0008)
               └─ stores ─┬─ products ── product_variants, product_relationships
                          ├─ workflows ── workflow_versions, workflow_runs   (0010)
                          ├─ action_requests                                (0010)
                          ├─ campaigns ── campaign_versions, campaign_group_members ── campaign_groups
                          ├─ contacts ── consent_events, provider_sync_jobs
                          ├─ provider_connections, integration_credentials
                          └─ (store_id, no FK) analytics_aggregates, metric_counters, experiment_stats,
                             conversions ── attribution_records, suppression_records, audit_logs, webhook_events
```

## Migration 0008 (platform foundation)

| Change | Why |
|---|---|
| `audit_logs` + `actor_type` (user/platform/system), `correlation_id`, `summary` (json); index `(organization_id, created_at)` | A workspace-level audit view, matching rows to requests, telling webhook and system actions apart |
| Backfill: `actor_type` for actor-less rows; `organization_id` from the store | Existing rows become visible in the workspace log |
| `domain_events` (unique `(organization_id, idempotency_key)`; indexes on `(store_id, recorded_at)` and `(status, recorded_at)`) | Store-then-deliver platform events (`docs/event-catalog.md`) |
| `domain_event_deliveries` (PK `(event_id, subscriber)`, cascade) | Per-subscriber idempotency on redelivery |

The migration only adds columns and tables; nothing is dropped or renamed. Its test runs it over seeded rows from
before 0008.

## Migrations 0009-0011 (entitlements, workflows, AI tasks)

| Migration | Change | Why |
|---|---|---|
| 0009 | `organization_features` (PK `(organization_id, feature)`, cascade) | Preview capabilities switched on per workspace |
| 0010 | `workflows` (draft definition, status, active version, activating member) | Automation drafts and their lifecycle |
| 0010 | `workflow_versions` (unique `(workflow_id, version)`) | Immutable activated definitions, like `campaign_versions` |
| 0010 | `workflow_runs` (unique `(version_id, trigger_key)`; indexes `(status, run_at)`, `(workflow_id, created_at)`) | One run per version and triggering event or day: the idempotency key. Steps are recorded as JSON |
| 0010 | `action_requests` (indexes `(store_id, status, created_at)`, `(plan_id)`) | The approval queue for workflow and AI actions; `plan_id` groups one AI plan's proposals |
| 0011 | `ai_generations` + `task`, `organization_id`, `provider`, `duration_ms`, `estimated_cost_usd`; backfill `organization_id` from the store | Usage and cost per AI task and workspace |

All three only add tables and columns; `packages/database/src/migration-0009-0011.test.ts` covers uniqueness,
cascades and the 0011 backfill. None has been applied to a real Cloudflare D1.

## Retention

| Data | Kept for |
|---|---|
| `event_dedup` | 3 days |
| `domain_events` | 30 days (delivered or pseudonymous) / 90 days (undelivered) |
| Contacts | Unconfirmed: 7 days. Not subscribed: 30 days |
| Store data | Until store purge, which deletes all of it |
